## 1. Guerrila operating thesis

V6.4-Guerrila is the small-treasury, experimental deployment profile.

It is designed to:
- dominate the broad field without paying top-tier infra rent,
- avoid direct public mempool / TPU warfare,
- avoid whale flow where larger competitors will outbid us,
- keep the engine inside the private auction shadows,
- preserve a fragile 150 SOL treasury while building data, confidence, and bankroll.

This phase is explicitly **not** the full-fat V6.4 expansion profile. It is the cheap, hard, survivable profile that lets the weapon earn the right to scale.

Core doctrine:
1. **Do not chase public flow.**
2. **Do not pay for SWQoS relays.**
3. **Do not provision Equinix-class infra yet.**
4. **Do not size into whale targets.**
5. **Do not allow any fallback that reopens public priority-fee bleed.**

## 2. Infrastructure amputation

### 2.1 Zero SWQoS budget

The Guerrila profile abolishes SWQoS relay spend.

Mandatory consequences:
- No staked QUIC relay budget.
- No paid public TPU racing infrastructure.
- No relay identities purchased or provisioned for public blast.
- No engineering time spent optimizing a lane that this profile forbids using.

The software may still support public relay fanout in the master V6.4 blueprint, but **Guerrila does not provision it**.

### 2.2 Commodity bare-metal server only

The Guerrila profile cancels any early Equinix-class rollout.

Mandatory deployment target:
- one high-end commodity bare-metal host,
- AMD EPYC class,
- 128 GB RAM minimum,
- a NIC that can actually run native XDP_ZEROCOPY on the chosen host (Mellanox ConnectX-4+ or Intel E810/X710 class; generic onboard NICs are not acceptable),
- enough NIC + storage performance to preserve AF_XDP, hugepages, and replay tooling,
- **region chosen by private-lane physics first**: the host MUST be physically adjacent to the dominant Jito/Harmonic ingress region for the intended deployment window. Frankfurt or Tokyo are acceptable only when they are actually the lowest-latency private-lane regions.

This is a cost decision, **not** a determinism waiver. The following remain mandatory:
- BIOS thermal / frequency discipline,
- AVX-512 thermal locks where applicable,
- `isolcpus`, `nohz_full`, `rcu_nocbs`,
- worker pinning,
- NUMA-local memory placement,
- hugepage reservation,
- IRQ-free poll-mode queues on Tier-0 paths,
- BIOS / NPS placement that keeps the NIC queues and the isolated Tier-0 cores on the same silicon die / NUMA locality domain.

### 2.3 Shared premium Geyser instead of dedicated enterprise node

Use a premium shared RPC/Geyser provider instead of a dedicated enterprise node.

Intent of this override:
- reduce monthly node spend,
- keep enough state visibility and fallback observability,
- accept slightly worse freshness only behind an explicit stale-state firewall.

Mandatory state-drift rule:
- `shadow-state` MUST continuously publish a monotonic Geyser freshness slot (`shadow_health.snapshot_slot` or equivalent).
- `shadow-state` MUST ingest live Token-2022 `SetTransferFee` changes from Geyser and refresh mint fee state during runtime; startup-only fee metadata is not sufficient.

Because Harmonic spends via native priority fees, stale shared state is not merely a quote error; it is a fee-burn risk. Guerrila therefore requires a worker freshness gate: if `ingress_record.slot - last_geyser_update_slot > harmonic_max_state_slot_lag`, the worker MUST strip the Harmonic route and attempt Jito instead if the private bundle path is still valid; otherwise it MUST drop. It MUST NOT send a stale-state Harmonic tx just because `ShadowGuard` would save principal later.

This does **not** reopen the public execution lane. Shared Geyser is supporting infrastructure, not a reason to chase public flow.

### 2.4 What remains live

The following stay active in Guerrila mode:
- AF_XDP raw shred ingestion,
- Jito bundle egress,
- Harmonic bundle egress,
- `shadow_leader_schedule`,
- dual tip LUTs,
- `shadow_nack_ring`,
- Rosetta Stone auto-heal,
- the Harmonic 1-Strike quarantine.

The cost cuts are about **transport and infra spend**, not about ripping out the safety model.

### 3.1 Meaning of these overrides

#### `system.proxies.egress.quic_workers: 0`
There is no public blast lane in Guerrila mode. Do not allocate threads, sessions, descriptors, or monitoring budget to a path that must never be used.

#### `submit.routing.default_public_geyser: drop`
If a target is observed through the public lane, discard it. Do not chase it. Do not build a TPU variant. Do not try to salvage it with a late public send.

#### `submit.routing.default_jito_searcher: jito_bundle`
Jito remains the primary private shadow lane.

#### `submit.routing.private_mempool_strategy: jito_bundle_if_compatible`
Private flow remains bundle-first. In Guerrila mode, this setting **must not** degrade back into public blast. If the private flow cannot be expressed safely as a bundle lane, the intent is dropped.

#### `submit.routing.enable_harmonic_lane: true`
Keep Harmonic live, but only behind:
- leader-schedule confirmation,
- exact Harmonic template rules,
- the Death Clamp on send failure,
- the mandatory 1-Strike Lethal Catch breaker.

#### `submit.quic.kamikaze_enabled: false`
Public QUIC racing is not part of this profile. Disable kamikaze mode for hygiene and to prevent accidental reactivation of dead public-lane code paths.

#### `risk.reserve_floor_sol: 10.0`
Keep the bot armed while preserving minimum operating liquidity.

#### `risk.max_position_sol_per_mint: 15.0`
Maximum single-asset exposure is capped at 10% of a 150 SOL treasury.

#### `risk.max_notional_sol_per_entity: 30.0`
Maximum aggregate exposure to one entity is capped at 20% of a 150 SOL treasury.

#### `state.geyser.harmonic_max_state_slot_lag: 1`
Harmonic is forbidden when shared Geyser state is more than one slot behind the observed intent. Guerrila is allowed to be clever, but not clever enough to pay native priority fees on stale math.

#### `state.geyser.require_live_transfer_fee_updates: true`
Token-2022 transfer fees must be streamed live from Geyser. Guerrila must not rely on startup-only metadata for fee-sensitive forward projection.

#### `state.clmm.publish_dist_to_tick_lamports: true`
If a supported CLMM adapter is enabled, `shadow-state` may publish only a single worker-visible scalar `dist_to_tick_lamports` (or an equivalently fixed-size sidecar keyed by `pool_index`). It MUST NOT push full tick-array structures into the worker.

#### `submit.routing.stale_harmonic_state_action: reroute_to_jito`
The freshness gate is not a blind alpha sacrifice. If Harmonic becomes unsafe because shared state is stale, the worker strips the Harmonic route and attempts a Jito bundle instead. If Jito is not valid, the intent is dropped.

#### `submit.routing.atba_route_mode: jito_only`
Any intent relying on within-tick compute determinism is Jito-only. If the tactic cannot be expressed as a Jito bundle, it is dropped.

#### `submit.routing.apex_partial_route_mode: jito_only`
Any >15 SOL full-curve opportunity that survives only as a 15 SOL clamped partial is Jito-only. Harmonic is forbidden for this tactic.

#### `submit.harmonic.cu_pad_units: 150`
Harmonic templates keep a microscopic fixed compute pad. This accepts a negligible steady overpay to avoid catastrophic `ComputationalBudgetExceeded` fee burns.

#### `submit.harmonic.quarantine_mode: specific_error_only`
The Harmonic lane is not amputated on every on-chain `Err`. Guerrila quarantines only on classified lethal causes: explicit `ShadowGuard` boundary breaches or Harmonic infrastructure failures. Generic retail-user slippage mistakes do not count.

#### `telemetry.observe_only.log_drop_reasons: true`
Observe-only mode must record why flow was rejected (`Dropped_Public_Target`, `Dropped_ApexNotPositive`, `Dropped_Harmonic_StaleState`, etc.).

#### `telemetry.observe_only.shadow_pnl_enabled: true`
Guerrila must compute a shadow PnL of what it refused to trade so graduation to the full V6.4 profile can be justified mathematically, not emotionally.

#### `oracle.guerrila.max_live_trade_input_sol: 15.0`
The live input corset is absolute. Guerrila may never deploy more than 15 SOL of actual input on one intent, even when the full-curve opportunity is larger.

#### `oracle.guerrila.micro_market_enabled: true`
Guerrila is allowed to use a worker-visible micro-market oracle because this profile is primarily an auction bot, not a public-lane speed war. The allowance is narrow: the worker may pay only for one extra fixed-array class-tag load and one banked LUT selection.

#### `oracle.guerrila.leader_class_count: 8`
Keep the leader partition coarse and fixed-size. Eight classes are enough to separate meaningfully different auction environments without fragmenting samples or forcing larger worker-side lookup structures.

#### `oracle.guerrila.publish_mode: banked_by_leader_class`
`shadow-oracle` publishes banked LUT snapshots by leader class, and `shadow-tier0` consumes them with O(1) index selection only. No hash maps, no model inference, and no per-intent search are allowed in the worker.

#### `oracle.guerrila.allow_clamped_apex_partials: true`
The oracle may salvage the steepest profitable slice of a >15 SOL full-curve opportunity by publishing a clamped ≤15 SOL partial. These partials are Jito-only.

#### `oracle.guerrila.allow_atba_jito_only: true`
ATBA is approved only in the Jito lane, where a revert costs 0 SOL. If CLMM state is missing, stale, or the tactic cannot be expressed as a safe Jito bundle, it is disabled.

#### `oracle.guerrila.obscurity_discount_enabled: true`
The oracle may discount Jito bids when a route looks obscure enough that generic competitor parsers are likely to fail, but the measurement must remain header-only and fixed-cost.

#### `oracle.guerrila.obscurity_mode: header_only_bitpacked`
Obscurity is measured only from O(1) header-adjacent features and consumed through a fixed-width bit-packed LUT index. Deep CPI traversal and a third dynamic array dimension are forbidden.

#### `oracle.guerrila.obscurity_initial_floor_bps: 4500`
The first live deployment must stay conservative. Even the highest-obscurity bucket starts around a 45% bid floor until shadow PnL proves that deeper discounts are safe.

## 4. Guerrila routing semantics

Guerrila changes **route permission**, not just route defaults.

### 4.1 Public lane is amputated

The `PUBLIC_GEYSER` execution lane is dead in this profile.

Mandatory behavior:
- If the decisive signal source is public, the worker MUST drop the intent.
- The worker MUST NOT build, sign, or enqueue a public TPU/QUIC variant.
- The system MUST NOT attempt a "better late than never" public send.
- The system MUST NOT provision any egress thread whose only purpose is public blast.

Public feeds may still exist for telemetry, state sanity, Rosetta calibration, or operator visibility. They are **not** an execution trigger in Guerrila mode.

### 4.2 Private flow stays inside private bundle rails

For `PRIVATE_MEMPOOL` and `JITO_SEARCHER_API` targets, the worker MUST stay inside bundle-compatible delivery paths.

Authoritative route fork:
1. If the target is public -> **drop**.
2. Else if `/dev/shm/shadow_leader_schedule` says the relevant slot is Harmonic, `enable_harmonic_lane == true`, `harmonic_quarantined == false`, and the Geyser freshness gate passes -> **Harmonic bundle**.
3. Else if the relevant slot is Harmonic but the Geyser freshness gate fails -> **Jito bundle if compatible and timing margin is satisfied; otherwise drop**.
4. Else if the route is Jito-compatible and timing margin is satisfied -> **Jito bundle**.
5. Else -> **drop**.

### 4.2.1 Harmonic freshness gate (mandatory)

The worker MUST compare the observed intent slot against the last confirmed shared-state slot from `shadow-state` using a saturating subtraction.

Reference comparison:
- `state_lag_slots = saturating_sub(ingress_record.slot, shadow_health.snapshot_slot)`

If `state_lag_slots > harmonic_max_state_slot_lag`:
- Harmonic is forbidden for that intent,
- the worker MUST strip the Harmonic route and evaluate Jito bundle routing,
- if a safe Jito route is unavailable, the worker MUST drop,
- the worker MUST NOT send the Harmonic priority-fee template on stale state.

**Note:** this is a zero-capital-bleed preference, not a speed indulgence. Jito preserves the alpha attempt without exposing the treasury to Harmonic priority-fee leakage when shared state is behind.


### 4.2.2 Jito-only tactical routes (mandatory)

Two Guerrila tactics are explicitly forbidden from the Harmonic lane:
- `atba=true` intents, which rely on within-tick compute determinism and razor-thin CU budgeting,
- `apex_partial=true` intents, which intentionally front-cut only the steepest profitable 15 SOL slice of a much larger curve.

Mandatory rule:
- if an intent is flagged `atba=true` or `apex_partial=true`, the worker MUST bypass Harmonic entirely,
- the worker MUST evaluate Jito bundle routing only,
- if Jito is not valid for that slot and timing window, the intent MUST drop,
- the worker MUST NOT reinterpret these tactics as permission to reopen any public path.

This is a treasury rule, not a preference. The tactic either lands in a zero-fee-burn Jito bundle context, or it does not run.

### 4.3 Guerrila-only `drop` action

For Guerrila mode, `drop` is a valid terminal routing action. It means:
- no envelope is built,
- no signature is emitted,
- no egress ring enqueue occurs,
- a lightweight reason code may be logged,
- the engine preserves capital and moves on.

### 4.4 No public fallback from private orderflow

The master V6.4 spec permits public fallback in certain private-flow cases. Guerrila explicitly forbids that.

In this profile:
- `jito_bundle_if_compatible` means "bundle if compatible, otherwise drop," not "bundle if compatible, otherwise public blast."
- stale-state Harmonic candidates MUST reroute to Jito only if Jito is valid for that slot and timing window; otherwise drop.
- Harmonic send failure MUST drop.
- Harmonic quarantine MUST reroute to Jito only if Jito is valid for that slot and timing window; otherwise drop.
- No path may reopen `PUBLIC_GEYSER` execution.

## 6. Oracle operational restraints

The Guerrila oracle does not hunt leviathans, but it is also not allowed to blind itself to profitable partial slices.

### 6.1 Hard live input cap and partial-whale policy

The hard corset is on **live input deployed**, not on the theoretical capital required to fully flatten an entire curve.

Mandatory rule:
- `shadow-oracle` MUST NEVER publish a live trade input greater than **15.0 SOL**,
- the worker MUST keep a final hard reject if `trade_input_sol > 15.0`,
- a >15 SOL full-curve opportunity is not auto-valid just because it exists.

For targets whose full correction exceeds 15.0 SOL, the oracle MUST choose one of only three outcomes:
1. **Plain within-cap intent** if the naturally optimal input is already ≤15.0 SOL.
2. **Clamped apex partial** if a ≤15.0 SOL front-slice still has positive conservative NetEV.
3. **Drop** if neither of the above is true.

This preserves the treasury corset without automatically discarding the steepest, most profitable section of larger curves.

### 6.2 Asymmetric Tick-Boundary Arbitrage (ATBA) — approved Jito-only tactic

**Note:** this tactic is dormant unless a supported CLMM adapter is enabled. It does not force immediate CLMM venue expansion in the first Guerrila rollout.

ATBA is allowed only under the following guardrails:
- `shadow-state` (or an equivalent off-path CLMM helper) does the heavy lifting off the hot path,
- the worker MUST NOT receive or traverse full tick arrays,
- the worker may receive only a single scalar `dist_to_tick_lamports` (or an equivalently fixed-size sidecar keyed by `pool_index`).

Worker rule:
- `trade_size = min(optimal_size, dist_to_tick_lamports - 1_lamport, 15_SOL)`

Routing rule:
- any intent relying on `dist_to_tick_lamports` or on exact within-tick CU density is **Jito-only**,
- ATBA MUST NOT enter Harmonic,
- if `dist_to_tick_lamports` is missing, stale, or non-positive, the tactic is disabled for that intent.

The purpose is simple: keep the worker O(1), keep CLMM state off the hot path, and keep any compute-density gamble in the zero-fee-burn bundle lane only.

### 6.3 Marginal Apex Harvesting — approved Jito-only tactic

A >15 SOL full-curve opportunity is allowed to survive as a **clamped apex partial** only when:
- actual deployed input remains ≤15.0 SOL,
- the partial still has positive conservative NetEV after competition assumptions,
- the intent is explicitly tagged `apex_partial=true`,
- the route is **Jito-only**.

Harmonic is forbidden for this tactic.

Reason:
- the whale competing for the full curve can outbid a 15 SOL slice in absolute terms,
- if the whale lands first, a second-place Harmonic partial can revert and burn priority fees,
- Jito drops are free; Harmonic mistakes are not.

Guerrila may therefore reclaim the convex front of the curve, but only inside the Jito lane and only inside the same 15 SOL treasury corset.

### 6.4 Tip LUT caps for retail mistakes only

In V6.4, tip logic is split across:
- `/dev/shm/shadow_tip_lut_base`
- `/dev/shm/shadow_tip_lut_jito`

Guerrila applies a conservative cap policy to **both**.

Mandatory rule:
- the LUTs MUST NEVER publish bid levels that assume we are fighting for whale-sized slippage mistakes,
- maximum dynamic bids MUST stay inside a mathematically safe fraction of the small retail errors this profile is designed to harvest,
- if a bucket requires a larger bid than the Guerrila cap policy permits, the oracle MUST clamp the bid or publish a value that causes the opportunity to be skipped.

Operational intent:
- Jito LUT remains tax-adjusted,
- base LUT remains true-validator-value,
- but both are capped to the small-treasury risk appetite.

Guerrila is not allowed to "accidentally scale" into a larger auction just because the LUT says it can.

### 6.5 Obscurity-discounted tip matrix (header-only)

Guerrila MAY discount Jito bids when the route looks obscure enough that generic competitor parsers are likely to fail, but this is allowed only in a strictly bounded form.

Mandatory measurement rule:
- obscurity MUST be derived only from O(1) header-adjacent features already present in the ingress path,
- acceptable signals include static account-key count, flat instruction count, and cheap static program-id flags such as visible Token-2022 involvement,
- deep CPI traversal, nested route decoding, or variable-time inspection in AF_XDP ingress is forbidden.

The ingress path MAY emit `obscurity_score ∈ [0,3]` in the fixed-size `IngressRecord`.

Worker consumption rule:
- workers MUST NOT look up a third dynamic array dimension,
- instead, obscurity is consumed through a fixed-width bit-packed bank index such as:
  - `final_index = (obscurity_score << 6) | (alpha_bucket & 0x3F)`
  - or an equivalent fixed-width scheme that keeps the bank L1-resident.

Calibration rule:
- the first live deployment MUST stay conservative,
- the highest-obscurity buckets may discount bids, but they MUST NOT jump straight to 15%,
- start around a floor near **45%** of the non-obscure baseline until shadow-PnL evidence proves that deeper discounts are safe.

### 6.6 Retail micro-market oracle (approved Guerrila exception)

Guerrila MAY use a **worker-visible** micro-market oracle, because this profile is competing mainly in private-lane auctions and the allowed implementation cost is negligible if kept fixed-layout.

Mandatory structure:
- `shadow-oracle` calibrates by at least `lane × leader_class × alpha_bucket`,
- it MAY incorporate `obscurity_score`, but only through fixed-width bucket packing,
- `shadow-state` publishes a fixed-size `leader_class_id` alongside the existing leader-engine tag for each scheduled slot,
- workers load that class tag with the same slot-mask pattern already used for `engine_tags`,
- workers select a bank from the existing Jito/base LUT snapshots and then perform the same bucket-round + multiply logic as before.

Hard limits:
- `leader_class_count` MUST stay small and fixed (`8` in Guerrila mode),
- no worker-side pubkey maps, hash tables, tree lookups, inference, or search are allowed,
- the retail cap policy still dominates every bank; class specialization must never widen the target set beyond the Guerrila treasury corset.

**Note:** this is the only approved Guerrila relaxation of the usual microsecond purism. If the implementation grows beyond one extra class-tag load, one fixed-width bank selection, and constant-time bit-packing, it is non-compliant with the Guerrila profile.

## 7. Harmonic usage in Guerrila mode

Harmonic remains enabled because it preserves private-lane optionality without reopening the public warzone.

However, it is strictly conditional:
- only use Harmonic when the leader-engine tag says Harmonic,
- only use Harmonic when `state_lag_slots <= harmonic_max_state_slot_lag`; otherwise strip Harmonic and attempt Jito if valid, else drop,
- only use Harmonic for **plain within-cap intents**,
- any `atba=true` or `apex_partial=true` intent MUST bypass Harmonic and evaluate Jito only,
- only use the exact Harmonic template with a microscopic fixed pad of **150 CUs**,
- never include the Jito tip transfer instruction on the Harmonic path,
- preserve the Death Clamp on send failure,
- preserve the refined 1-Strike Lethal Catch: quarantine only on classified lethal causes (`ShadowGuard` boundary breach or Harmonic infrastructure failure), not on generic retail-user slippage mistakes,
- never fall back to public TPU blast if Harmonic fails or leaks.

**Note:** the 150-CU pad is intentionally microscopic. Guerrila accepts a trivial steady overpay to avoid catastrophic fee burns from occasional `ComputationalBudgetExceeded` reverts.

In Guerrila mode, Harmonic is an opportunistic edge, not a mandatory dependency. The highest-risk density tactics stay in Jito or do not run.

## 9. Operational success criteria

A Guerrila deployment is considered correct only if all of the following are true:
- monthly infrastructure spend is held near the $1,000 target,
- no public-lane egress threads are provisioned,
- public-observed targets are dropped rather than chased,
